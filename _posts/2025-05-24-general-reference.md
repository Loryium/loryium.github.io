# General Reference

这是一份用于记录想法、整理文章和快速查 Markdown 格式的 all-in-one 规范文档。它基于当前 `_posts` 里的写法整理，适合直接复制片段到新文章中使用。
Generated by AI, not by me.

## 1. 文件命名

文章放在 `_posts` 目录下，文件名建议使用：

{% highlight text %}
YYYY-MM-DD-topic-name.md
{% endhighlight %}

示例：

{% highlight text %}
2025-05-24-general-reference.md
2026-01-15-reading-notes.md
2026-02-03-project-idea.md
{% endhighlight %}

建议：

- 日期使用文章创建日期。
- 英文单词用小写。
- 单词之间用 `-` 连接。
- 文件名只表达主题，不必写完整标题。

## 2. 文章头部 Front Matter

每篇文章开头都需要一段 front matter，用 `---` 包起来。最常用格式如下：

{% highlight yml %}
---
layout: post
title: "文章标题"
date: 2026-01-15 20:30:00
description: 一句话摘要，会出现在列表或 RSS 中。
tags:
 - note
 - idea
toc: true
comments: false
share: false
---
{% endhighlight %}

字段说明：

| 字段 | 是否常用 | 作用 |
|------------ | ------------- | ------------- |
| `layout` | 必填 | 使用博客文章布局，通常固定为 `post`。 |
| `title` | 必填 | 文章标题。包含冒号、引号等符号时建议加双引号。 |
| `date` | 推荐 | 发布时间，格式为 `YYYY-MM-DD HH:mm:ss`。 |
| `description` | 推荐 | 文章摘要，控制在一句话内。 |
| `tags` | 可选 | 标签列表，用于归档和分类。 |
| `toc` | 可选 | `true` 时显示目录，适合长文。 |
| `comments` | 可选 | `true` 时开启评论；当前站点默认关闭。 |
| `share` | 可选 | `true` 时显示分享按钮；当前站点分享按钮默认关闭。 |
{:.wide}

最小可用版本：

{% highlight yml %}
---
layout: post
title: "文章标题"
date: 2026-01-15 20:30:00
description: 一句话摘要。
---
{% endhighlight %}

## 3. 标题层级

推荐从一级标题 `#` 开始写文章正文标题，然后按层级递进：

{% highlight markdown %}
# 一级标题：文章主标题或大主题

## 二级标题：主要章节

### 三级标题：章节下的小节

#### 四级标题：细节、步骤、补充说明
{% endhighlight %}

建议：

- 一篇文章通常只使用一个 `#` 一级标题。
- 主要结构使用 `##`。
- 细分内容使用 `###`。
- 不要为了视觉大小跳级，例如从 `##` 直接跳到 `####`。
- 开启 `toc: true` 时，清晰的标题层级会让目录更好用。

## 4. 段落与换行

普通段落直接写文本即可。段落之间空一行：

{% highlight markdown %}
这是第一段内容。可以记录背景、问题、观察或结论。

这是第二段内容。段落之间保留一个空行，阅读体验会更清晰。
{% endhighlight %}

在当前配置中，`kramdown.hard_wrap: true` 已开启，普通换行也会比较友好地显示。不过为了兼容性，仍建议用空行分隔段落。

## 6. 列表

无序列表适合记录并列事项：

{% highlight markdown %}
- 第一项
- 第二项
- 第三项
{% endhighlight %}

有序列表适合记录步骤：

{% highlight markdown %}
1. 先记录问题。
2. 再写观察。
3. 最后写结论或下一步。
{% endhighlight %}

建议：

- 同一列表中尽量保持语法结构一致。
- 步骤、流程、优先级使用有序列表。
- 想法、材料、要点使用无序列表。

## 8. 表格

普通表格：

{% highlight markdown %}
| 项目 | 说明 | 状态 |
|------------ | ------------- | ------------- |
| 想法来源 | 为什么想到这件事 | 已记录 |
| 当前判断 | 现在怎么看 | 待验证 |

{% endhighlight %}

效果：

| 项目 | 说明 | 状态 |
|------------ | ------------- | ------------- |
| 想法来源 | 为什么想到这件事 | 已记录 |
| 当前判断 | 现在怎么看 | 待验证 |
| 下一步 | 接下来要做什么 | 未开始 |

宽表格可以在表格后追加 `{:.wide}`：

{% highlight markdown %}
| 维度 | 问题 | 观察 | 结论 |
|------------ | ------------- | ------------- | ------------- |
| 背景 | 这件事为什么重要 | 当前已有的信息 | 暂时的判断 |
| 风险 | 可能哪里会失败 | 需要验证的条件 | 预案 |
{:.wide}
{% endhighlight %}

内边框表格可以在表格后追加 `{:.inner-borders}`：

{% highlight markdown %}
| A | B |
|------------ | ------------- |
| 1 | 2 |
| 3 | 4 |
{:.inner-borders}
{% endhighlight %}

对齐方式：

{% highlight markdown %}
| 默认 | 左对齐 | 居中 | 右对齐 |
|------------ |:------------- |:-------------:| -------------:|
| A | B | C | 100 |
{% endhighlight %}

建议：

- 表格适合对比、状态追踪、参数整理。
- 普通笔记不要过度使用表格，避免后期维护麻烦。
- 长内容优先拆成列表或小节。

## 10. 图片

图片建议放在 `assets/images/` 下，然后用 `relative_url` 引用。

行内图片：

{% highlight liquid %}
{% raw %}
![图片说明]({{ '/assets/images/example.png' | relative_url }})
{% endraw %}
{% endhighlight %}

居中图片：

{% highlight liquid %}
{% raw %}
![图片说明]({{ '/assets/images/example.png' | relative_url }}){: .center-image }
{% endraw %}
{% endhighlight %}

带简短说明：

{% highlight liquid %}
{% raw %}
![图片说明]({{ '/assets/images/example.png' | relative_url }}){: .center-image }*图片说明文字*
{% endraw %}
{% endhighlight %}

建议：

- 图片文件名使用小写英文和 `-`。
- 图片说明写清楚图片内容，不要只写 `img`。
- 大图、截图、流程图优先使用居中图片。

## 12. 标签规范

标签放在 front matter 里：

{% highlight yml %}
tags:
 - note
 - idea
 - reading
{% endhighlight %}

建议维护一组稳定标签：

| 标签 | 用途 |
|------------ | ------------- |
| `note` | 普通笔记 |
| `idea` | 灵感、想法、待探索主题 |
| `reading` | 读书、文章、论文记录 |
| `project` | 项目计划、开发记录 |
| `reference` | 规范、模板、资料索引 |
| `life` | 生活记录 |
| `study` | 学习记录 |
{:.wide}

如果新增标签，记得检查 `tag` 目录是否需要增加对应标签页。

## 13. 想法记录模板

适合记录一个还不成熟的想法：

{% highlight markdown %}
# 想法标题

## 背景

这个想法从哪里来？当时遇到了什么问题或看到了什么现象？

## 核心想法

用一两段话说清楚它是什么。

## 为什么重要

- 它解决了什么问题？
- 它和现有做法有什么不同？
- 它对我有什么价值？

## 当前判断

| 维度 | 判断 |
|------------ | ------------- |
| 可行性 | 高 / 中 / 低 |
| 成本 | 高 / 中 / 低 |
| 价值 | 高 / 中 / 低 |
| 不确定性 | 最大的不确定点是什么 |

## 下一步

1. 第一个可执行动作。
2. 需要查的资料。
3. 需要验证的假设。
{% endhighlight %}

## 17. 写作检查清单

发布或归档前可以快速检查：

- front matter 是否完整。
- `title` 和文件名是否能表达主题。
- `description` 是否是一句话摘要。
- 长文是否开启 `toc: true`。
- 标题层级是否从 `#`、`##`、`###` 顺序递进。
- 表格是否需要 `{:.wide}`。
- 图片路径是否使用 `relative_url`。
- 代码块语言是否写对。
- 标签是否稳定、可复用。
- 最后是否有结论或下一步。
